# 治理

## 1. 谁能合并

- 官方命名空间与 `cn.ai4energy.esml` 坐标：维护者评审后合并。
- 社区坐标：维护者只校验格式与依赖，不评审模型内容；内容的正确性由作者与使用者负责。

## 2. 命名空间

- 官方：`Units`、`Connectors`、`Thermal`、`Fluid`、`CompressedAir`、`Electrical`、`Control`、`Storage`、`Renewable`、`Examples` 及其点分子段（如 `Examples.Thermal`）。
- 社区：至少两段，例如 `Com.Example`；首段不得使用官方保留集合中的名字。
- 命名空间一经分配不回收；包弃用后命名空间仍保留，避免旧文档解析到别的包。

## 3. 版本

- 发布即不可变；指纹是承诺。
- 弃用要给替代坐标与迁移说明。
- 删除注册行是禁止的；历史坐标必须继续可解析（可标记 `deprecated`）。

## 4. 依赖

- 只允许从领域包指向基础包，或从场景包指向领域包。
- 同层横向依赖需要架构评审：先问「能不能抽出一个更底层的包」。
- 依赖必须有版本；BOM 只提供默认值，不替代显式声明。

## 5. 许可

- 官方包：MIT。
- 社区包：OSI 认可许可证，SPDX 标识写入注册表。
- 不得注册许可证不明或与 ESML 使用场景冲突的包。

## 6. 变更记录

每次注册表变更在 PR 描述中写三件事：新增/修改哪个坐标、为什么、影响了哪些依赖。注册表本身是审计记录，不靠回忆。
